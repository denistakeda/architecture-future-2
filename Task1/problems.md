# Проблемные места

**1. DWH не справляется с текущей нагрузкой**

Разные бизнес-линии конкурируют за общие ресурсы, что может приводить негативному влиянию их друг на друга. Долгое проведение аналитики. Долгое построение отчетов.

**2. Использование устаревших технологий**

SQL server 2008 не предназначен для работы с большими данными в текущем понимании. Дальнейшее масштабирование невозможно. Использование SQL server в компании приведет к остановке процессов аналитики.

**3. Зависимости от фреймворков**

Apache Camel требует внедрения единого подхода к работе с данными. Компания планирует расширяться и зависимости от фреймворков будут негативно сказываться на сроках интеграции. Кроме того Apache Camel так же плохо адаптирован под высокую нагрузку. В Apache Camel обнаружены критичичные уязвимости, которые могут позволить злоумышленникам запускать вредоносный код внутри инфраструктуры.

**4. Уязвимости в безопасности**

Отсутсвует разграничение прав доступа. В результате сотрудник может получить доступ к данным, которые ему не должно быть доступа.

**5. Неудобство работы с данными**

Большой объем информации. Непонятно, в какой витрине искать данные для отчетов и есть ли они в хранилище. Затрудняет построение отчетов. Бизнес не может расчитывать на то, что специалист сделает свою работу вовремя и качественно. Создает зависимость от ключевых сотрудников, которые являются носителями знаний о системе.

# Приоритезация

*По MoSCoW*

### Must (обязательно)

Создание новой системы для хранения данных. Без решение этой задачи неважно, какие мы сделаем еще улучшения, система не будет работать

### Should (нужно)

Управление пользователями, разграничение прав доступа. Предотвратим возможные утечки данных и неконтролируемое использовании информации

### Could (желательно)

Убрать зависимости от фреймворков на уровне компании. Включение в собственную инфраструктуру новых компаний будет осложнено долгим процессом интеграции
Внедрить каталог данных. Можно какое-то время жить без него, но будут тратиться лишние часы на создание отчетов

### Won’t Have this time (можно перенести)

Полный отказ от устаревших технологий. Можно откладывать, так как нет существенного влияния на бизнес
